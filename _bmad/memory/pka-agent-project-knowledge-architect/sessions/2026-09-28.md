## Session — ShowCraft 初始架构

**What happened:** 用户指定从 system-build 安装 PKA 到 ShowCraft，并要求生成产品架构方案。

**Key outcomes:**
- PKA 已注册到项目 BMad 配置与帮助目录。
- 基于现有骨架计划创建三维“结构—运行—机制”项目知识架构。

**Observations:** 用户重视可生成且可演进的项目架构；真实产品与供应商细节尚未提供。

**Follow-up:** 在真实产品环境、HyperFrames 契约和品牌规范到位后，登记问题并刷新相应视图。

## Session — MVP 架构澄清

**What happened:** 用户确认了首发用户、事实输入、本地自动化和内容审核规则。

**Key outcomes:**
- 运营团队以 GitHub/本地 Changelog 为版本事实源，在本地自动生成面向用户的推广视频。
- 视频按特性数量伸缩，使用中文 AI 配音与字幕，发布前必须人工审核。

**Follow-up:** 澄清 Changelog 格式、本地产品启动/认证、时长公式、TTS 供应商与审核标准；以真实样本验证。

**Consistency check:** Changelog、音画与人工审核已分别具备结构、运行和机制承载；本地 runner 保持 CLI 形态，暂不引入队列或服务。

## Session — 输入与审核实现条件

**What happened:** 用户确定 Changelog 通过 CLI 文档地址传入，首个目标产品为 StartUpOS，并确认动态时长与视频链接审核方式。

**Key outcomes:**
- StartUpOS 发布说明默认约定为 `docs/changes/releases/v<version>/changelog.md`，但 `--source` 显式路径优先。
- CLI 输出视频链接，用户决定批准或退回；时长规则为开场/结尾 10–15 秒、每项特性 12–20 秒、超过 90 秒拆分。

**Follow-up:** 明确 StartUpOS 启动/认证、解析与 TTS 适配器、链接服务和审核标准。

## Session — 首发验收样本

**What happened:** 用户选定 StartUpOS Desktop、v0.3.3、Edge TTS 和 HTTP 预览。

**Key outcomes:**
- `v0.3.3` 发布说明已只读验证，包含可映射的四组功能主题。
- 首发新增 desktop runner、Edge TTS 和仅本机监听的预览服务三个架构适配器。

**Follow-up:** 确定桌面可录制流程、TTS 降级与人工审核标准，然后可更新实现计划。
