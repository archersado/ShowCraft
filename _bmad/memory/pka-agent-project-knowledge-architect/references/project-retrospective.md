# 项目复盘

把项目经历转化为下次可调用的经验，而不是重述时间线。消费者是未来面对相似情境的人或 Agent；他们需要知道模式何时适用、为什么可信、何时不该套用。

基于项目总览、三维架构、追踪关系、代码／交付结果、已有里程碑材料和 `verified`/`closed` 问题记录，比较目标与结果，识别被验证或证伪的假设、关键决策及其后果。未通过关闭门禁的问题只能作为待验证输入，不能产出已验证经验。将结论写入 `retrospectives/`，每个模式候选包含触发条件、相关结构模块、运行行为、设计机制、结果、证据、来源 `Q-ID` 和适用边界。

单项目只能产生模式候选，不能宣称跨项目规律。证据不足的解释保持待验证；不要为了完整而制造教训。原始项目文件只读。
