# 跨项目主题聚合

从多个项目中形成高于单项目的认知，同时保留它由哪些项目、哪些证据支撑。消费者是规划新项目、比较实践和升级个人方法论的人；主题应可迁移，但绝不能假装普遍真理。

只读取 `knowledge_hub_root/projects.yaml` 登记的项目知识目录，不直接扫描原始项目。按 [结构—运行—机制视图](view-model.md) 横向比较项目中的结构组成、运行行为、设计机制、追踪缺口、`verified`/`closed` 问题和复盘候选；开放问题只能形成待验证提示。至少两个项目提供独立证据后，才可在 `knowledge_hub_root/themes/` 创建或晋升正式主题。

每个主题写清核心认知、共同模式、关键差异、适用条件、反例、来源矩阵、置信度和待验证问题；`themes/index.md` 记录状态与来源项目。聚合结果不得写回任何项目。若只有一个项目支持，保持为该项目内的模式候选。
