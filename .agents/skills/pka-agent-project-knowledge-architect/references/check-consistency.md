# 架构一致性检查

找出项目模型中“说了要做，但没有结构承载”“结构存在，但没有运行行为使用”“行为存在，但机制和目标不清楚”的断裂。消费者是要决定下一步修正什么的项目负责人或架构师。

按 [结构—运行—机制视图](view-model.md) 检查业务、产品、技术各自的闭环，以及三类架构之间从业务目标到产品行为再到技术实现的映射。每个发现写清受影响对象、证据、断裂类型、实际风险和最小修正方向；不把文档格式差异或合法旧文件名当成架构问题。

优先更新 `traceability.md` 中的缺口状态，并在回复中给出按影响排序的结果。仅在用户需要可交付报告时生成独立 Markdown 或 HTML。检查过程只读原始项目文件，不自动修复项目或知识模型。

当检查由某个 `Q-ID` 的关闭门禁触发时，同时核对问题文件中的成功判据、实际架构更新和验证证据。通过时可将问题更新为 `verified`，随后关闭为 `closed`；失败时记录断裂并转为 `reopened`。状态更新只是记录检查结果，不得借此自动修复架构内容。
