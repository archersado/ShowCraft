# 刷新项目模型

让项目知识模型跟随真实项目变化，同时保留结论为何变化的解释。消费者需要快速知道新增了什么、旧认知哪里失效、哪些跨层映射开始漂移。

以现有 `sources.md` 和项目知识文件为基线，按 [结构—运行—机制视图](view-model.md) 只读识别新增、变更或消失的来源。更新受影响的结构、运行、机制和追踪关系；不要无差别重写未受影响内容，也不要自动重命名旧项目视图。给出变更摘要，区分新增事实、修正推断、失效结论、证据冲突和新的待验证项。

若新增证据关联到开放的 `Q-ID`，在对应问题文件中追加证据影响并更新 `issues/index.md` 的时间；不得仅因发现新材料就自动越过决策、更新或关闭门禁。若证据推翻已关闭问题的关键前提，将其标记为 `reopened` 并说明原因。

刷新只修改 `{output_folder}/project-knowledge/` 内的生成物。原始需求、方案、代码和交付物不得改变。若无法可靠判断变化范围，先报告需要用户确认的范围，不假装完成全量刷新。
